# HITMAN とのすり合わせ方

2026-11-07 に決めました。HITMAN と仕様を合わせる時に出る食い違いは、この手順で直します。

## 何を正しいとするか（上ほど強い）

1. 利用者の指示（チャットで言われたこと）
2. 利用者がくれた資料（S01〜S09。とくに武器194項目の表 S08 と、全仕様の要約 S09）
3. 自分で調べたこと（出典をつける）
4. 今の実装

## 食い違いを見つけたら

1. [台帳](hitman-decisions.md)に1行足します（正本は `app/src/data/hitman-decisions.json`）。HITMAN ではどうか、今はどうか、どこに書いてあるかを書きます。
2. 下の決まりで「合わせる」「わざと違える」「利用者に聞く」のどれかにします。
3. 決まったら、試験を先に書きます。試験には台帳の id（HD01 など）を書き、資料の行も引きます。
4. 作ります。
   - 画面は UI ラボで作ります。
   - 動きはアニメーションラボ、AI は AI ラボで確かめます。
5. ROADMAP の状態を直し、`npm run spec` を通します。
6. 1つの食い違いを1つのコミットにして、メッセージに id を書きます。

## どれにするかの決まり

| 場合 | 決め方 | だれが決める |
|---|---|---|
| 資料に書いてあり、利用者の指示とぶつからない | 合わせる | Claude が決めてよい |
| 利用者の指示とぶつかる | わざと違える。試験で固定し、HITMAN に合わせる作業でも戻さない | 利用者の指示どおり |
| 資料に無い、資料どうしが食い違う、遊び方が大きく変わる、ゲームの画面が大きく変わる | 利用者に聞く。台帳に選択肢を書き、まとめて聞く | 利用者 |
| 見た目・名前・人物・モデル | いつも CLEAN HANDS のもの（HD02） | 方針 |

## 前の試験とぶつかった時

- HITMAN に合わせると、前の決まりを確かめる試験が失敗することがあります。
- 試験を書き換えてよいのは、台帳にその理由がある時だけです。書き換えた試験にも id を書きます。
- 理由がない時は、作った方を疑います。

## 台帳の試験

`tests/hitman-decisions.test.ts` が次を確かめます。

- 「合わせる」「わざと違える」と決めた行は、書いてある試験ファイルにその id がある。
- 「利用者に聞く」の行には、質問と選択肢がある。
- ROADMAP で状態が D（資料と実装の差）の行は、台帳のどれかの行が引いている。
- `docs/hitman-decisions.md` が台帳と同じ。
