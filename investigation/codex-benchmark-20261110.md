## 3. 決まり

- 報告は日本語で、短く分かりやすく書きます。
- 各作業で頼まれた所だけを変えます。ついでの整理、名前の変更、書式の統一はしません。
- ゲームの画面（UI）は変えません。作業7の画面の案は UI ラボだけに作ります。
- 作業ごとに1コミットにします（作業1はコミットしません）。メッセージは英語で書き、先頭に `bench N:` を付けます。
- `git add` はファイル名を指定します。`git add -A` や `git add .` は使いません。
- **push はしません。** `main` にもマージしません。GitHub の `stupidsavacan/clean-hands` には絶対に触りません。
- 行末を変えません。ファイルによって CRLF と LF が混ざっているので、元と同じ行末で保存します。コミットの前に `git diff --stat` を見て、触っていない行が大量に変わっていないか確かめます。
- 試験を通すために、試験の期待値をゆるめたり消したりしません。
- 長い試験（歩くゴースト）は回しません。`npm run test:fast` を使います。
- 作り直せるページ（`index.html`、`club-prototype.html` など）は git に入れません。
- 決まっていないことを自分で決める必要が出た時は、案を書いて報告し、いちばん無難な方で進めます。

### 作業1　調査：要人が車に着かない理由（直さない）

- やること：理由を調べ、直し方の案を書きます。ファイルは直しません（調べるための一時的な書き換えは、最後に元に戻します）。
- できたら：

  - 根拠の数字を書いている（例：位置、距離、当たり判定や歩ける場所の調べた結果）。

### 作業2　道具：地図の点検を検証ステージでも使えるようにする

- 今：`npm run map:check` はクラブだけを点検します（`app/scripts/map-check.ts`）。
- やること：`--map <名前>` を足し、`npm run map:check -- --map test-stage` で検証ステージ（`app/src/data/test-stage-layout.json`）を点検できるようにします。`--json` と `--route` も、`--map` と一緒に使えるようにします。
- できたら：
  - `--map` を付けない時の出力は、今と1文字も変わらない。
  - `--map test-stage`、`--map test-stage --json`、`--map test-stage --route x,z,f x,z,f` が動く。
  - 知らない名前では、分かる文で止まる。
  - 試験を足している。
  - 検証ステージで見つかった問題は、直さずにそのまま報告に書いている。

### 作業3　仕様：バールで鍵のかかった扉をこじ開ける（検証ステージ）

- 今：`app/tests/item-spec.test.ts` に `test.todo('S08 row 3 crowbar: opens locked things …')` があります。扉の仕組み（`app/src/doors.ts`）には `pryable` がありますが、どの地図にもこじ開けられる扉がありません。
- やること：
  1. 検証ステージに、鍵のかかった小部屋を1つ足します。扉は鍵が必要で、`pryable` です。
  2. `build-map.ts` で地図を作り直します。
  3. TODO を本物の試験にします。
- できたら：
  - 試験で、次を確かめている。
    - バールを手に持つと「バールでこじ開ける」が出て、扉が開く。
    - バール以外（素手・スパナ）では開かない。
    - `pryable` でない鍵の扉は、バールでも開かない。
    - 開けた時に `item.used`（crowbar）が出る。
  - `npm run map:check -- --map test-stage` で、新しい問題が増えていない（作業2を使う）。
  - `test-stage.html` で実際にバールを持って扉の前に立ち、「E バールでこじ開ける」が出て開くことを確かめ、画像を2枚（開ける前・開けた後）残している。

### 作業4　モデル：Kali Stick（籐の棒）

  - 長さ 0.71 m、太さ 0.025 m。
  - 節を2〜3か所、少し太い輪で表します。
  - 両端は少し丸くします。
- 決まり：`assets/items/README.md` に従います。
  - 16色パレット、平らな面、roughness 1、1つ1GLB、メートル。
  - 握る点が原点（`GRIP_R`）で、柄から +Z へ伸びます。握る点は根元から 0.12 m です。`TIP` は先端です。
  - 三角形は 96 以下にします。
- できたら：
  - `node assets/items/source/validate.cjs` で、全部がエラー0・警告0。
  - README の表に1行足している。
  - `app/scripts/embed-items.mjs` で `app/src/item-data.ts` を作り直している。
  - 持ち物ラボ（`item-lab.html`）に Kali Stick が出て、「すべて自動判定」が全部合格する。

### 作業5　動き：バールで扉をこじ開ける（アニメーションラボだけ）

- やること：アニメーションラボに新しい動き `crowbar-pry` を足します。ゲームには入れません。
- 場面：
  - エージェントが、右手にバールを持って扉に向かって立ちます。
  - 扉の面は、正面 0.55 m の所にあります。
  - こじ開ける隙間は、扉の面の高さ 1.05 m です。
- 流れ（全体 1.6 秒）：
  1. 0.0〜0.3 秒：両手でバールを構えます。右手は握る点、左手は右手より 0.25 m 先です。
  2. 0.3〜0.5 秒：バールの先端を隙間に差し込みます。
  3. 0.5〜1.2 秒：腰を落とし、上体を後ろへ傾けて、体重をかけて引きます。
  4. 1.2〜1.6 秒：構えに戻ります。
- できたら：
  - ラボの既存の自動判定（肘・手足の判定）が、この動きでも全部合格する。
  - 次の数字を試験で固めている。
    - 0.5〜1.2 秒の間、バールの先端が隙間から 0.03 m 以内にある。
    - 全体を通して、左手がバールの軸から 0.03 m 以内にある。
    - 両足が 0.02 m 以上ずれない。
    - 0.9 秒の時、腰が構えより 0.06 m 以上低く、上体が 10° 以上後ろへ傾いている。
  - 画像を3枚（正面・横・0.9 秒）残している。

### 作業6　AI：目撃者は、知らせに行く警備が倒れたら次の警備へ向かう（AI 実験ステージ）

- 今のエンジンでは、殺害を見た客は近くの警備へ走って知らせます（`app/src/ai.ts` の `report`、走る先は毎回いちばん近い警備）。
- やること：`app/src/labs/ai-scenarios.ts` に、この動きを確かめる場面を足します。
  1. 客が殺害を見て、警備 A へ走る。
  2. 途中で A が気絶させられる。
  3. 客は警備 B へ向きを変えて着き、B が知らせを受ける。
- これは今の動きを確かめる作業です。**エンジン（`ai.ts`、`detection.ts` など）は変えません。**
- できたら：
  - 場面が、ページ（`ai-lab.html` の自動判定）と `app/tests/ai-lab.test.ts` の両方で合格する。
  - 判定は、途中の段階（A へ向かう → A が倒れる → B へ向かう → B が知る）を1つずつ確かめている。
  - 合格しない時は、エンジンを直さず、場面もコミットしない。何秒目に何が起きたかの記録を付けて報告する。

### 作業7　画面：背中の2枠の表示案（UI ラボだけ）

- 背中には、刀や Kali Sticks を2本まで背負えます（手に持っている物とは別）。今の画面には、背中に何があるかの表示がありません。
- やること：UI ラボ（`app/src/labs/ui-lab.ts`）に、背中の2枠の表示の案を2つ作ります。ゲームには入れません。
  - 2枠の状態は、空・刀・Kali Sticks のどれかです。
  - どちらかを手に持っている時は、その枠を「手に持っている」と分かる見た目にします。
- できたら：
  - iPad 横持ち（1080×810）と PC（1920×1080）の両方で、はみ出し・重なり・切れがない。
  - 色と文字は、今のゲームの画面（`app/src/hud-hitman.ts`）に合わせている。
  - それぞれの案で、状態の組み合わせ（空2つ・刀1本・刀2本・刀と Kali・手に持っている）を並べた画像を残している。
