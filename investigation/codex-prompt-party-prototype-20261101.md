# Codex への依頼：パーティー会場の試作マップ（HITMAN 型のマップの作り方を試す）

先に `investigation\codex-working-guide.md`（作業の仕方）を読んでください。この依頼は、そのやり方に従う前提で書いています。

**前の依頼（`codex-prompt-playtest2-20261101.md`、プレイテスト2回目の修正）が終わってから始めてください。**

## なぜ作るか

- ホテルのつながりを測ると、HITMAN のマップの作り方と逆の形でした。
  - 部屋がすべて外の地面にぶら下がっていて、部屋同士は直接つながっていません。
  - 大事な場所5か所が、入口1つの行き止まりです。
  - スタッフ用の裏の通路がありません。
  - 上下の移動は階段4本だけです。
  - 部屋の中は、区切りのない四角い箱です。
- 詳しくは次の2つを読んでください。
  - `investigation\hitman-map-comparison-20261101.md`（比較と出典）
  - `investigation\map-structure-audit-20261101.md`（いまの仕組みで書けること・書けないこと）
- ホテルを作り直す前に、**小さな新しいマップで、作り方が本当に面白くなるかを確かめます。** その試作の場が、このパーティー会場です。

## 目標：このマップで確かめたいこと

1. **スイスチーズ**：大事な場所ほど、入り方が複数ある。行き止まりが少ない。
2. **かたつむり**：表（誰でも入れる）から奥（私的な場所）へ、層が巻くように重なり、層と層が複数の道でつながる。
3. **表と裏の動線**：スタッフの服で、表とは別の、裏の道がつながっている。
4. **上下の抜け道**：階段のほかに、はしご・雨どい・窓・縁で、階や部屋を行き来できる。
5. **社会的な空間**：誰が入ってよい場所かが、そこにいる人と作りから分かる。区域の決まりと、そこで働く人の服が合っている。

## 守ること

- **ホテルの遊び（`index.html`）の動作は変えない。**
  - ホテル用のテストは、すべて通したままにしてください。
  - 共通の仕組み（`ai.ts`・`world.ts`・`nav.ts`・`m3.ts`・`m4.ts`・`detection.ts`・`combat.ts` など）に足すのはかまいません。ただし、足したものはホテルでは使われないか、使われても動作が変わらないようにしてください。
- **値はJSONに置く。** マップは、ホテルと同じく、生成用のスクリプト（新しく `scripts/build-party.ts`）から作ってください。
- **既存の仕組みを使う。**
  - 人のAI、服と区域の許可、顔を知る人、検問、気絶・排除・運ぶ・隠す、監視カメラ、撃ち合い、採点は、そのまま使ってください。
  - ホテル専用のもの（`m53.ts`・`m57.ts` は、ホテルの人の id を直接書いています）は使わず、このマップ用のチャンスは別に作ってください。
- **触らないもの**
  - モバイル版（`outputs\m55-mobile`）とサイトへの公開
  - プレイテストの道具（`outputs\m5-prototype\playtest\`）。このマップに対応させるのは、あとで Claude が行います。そのために、デバッグ用の入口 `window.__cleanHands` は、ホテルと同じ名前と使い方で用意してください。
  - git のコミットとプッシュ

## 作り方の決まり（ユーザーと決めたこと）

まだ決まっていない細かいことは、次の初期値で進めてください。報告で、どう決めたかを書いてください。

| 項目 | 初期値 |
|---|---|
| 舞台 | 夜の私邸でのパーティー。館1軒と、その庭 |
| 広さ | 館と庭で、およそ 60m × 45m。ホテル（129m × 74m）よりずっと小さく、密にする |
| 階 | 地下（ワインセラー、使用人の通路）、1階（玄関ホール、舞踏室、食堂、厨房、使用人の部屋）、2階（舞踏室を見下ろす回廊、客室、書斎、主寝室）、屋根裏（物置、屋根への出口）の4つ。ほかに、庭（東屋・温室）、使用人の出入り口と中庭、車庫 |
| 標的 | 1人（館の主人）。30分の中で、表の場所（舞踏室・庭）と奥の場所（書斎・主寝室）を行き来する |
| 人数 | 50〜70人（客・給仕・料理人・警備・護衛） |
| 動かない人 | 全体の3割以下。7割以上は、巡回の点を2つ以上か、予定で動かす（ホテルは120人中92人が動かない） |
| 抜け道を NPC も使うか | **使わない**（今回はプレイヤーだけ）。NPC の道は、今のナビのまま |
| ドア | 今回は作らない。ホテルと同じく、壁の開口にする |
| チャンス | 3つ。少なくとも1つは事故 |

## 作業1：設計を先に書いて、止まる

**座標を書く前に、つながりの設計を書いてください。** ここでいったん止まり、ユーザーの確認を受けます。

1. `investigation\party-design.md` に、次を書いてください。
   - **区域の一覧**
     - 名前、階、広さ
     - 種類：社会的な空間の6種類（誰でも入れる公共、目的のある公共、決まりの強い公共、私的、職業の場、個人の場）のどれか。あわせて、ゲームの区域の種類（公共・スタッフ・警備・外部）と、入れる服
     - そこにいる人
   - **出入り口の一覧**
     - どの区域とどの区域のあいだか
     - 種類：表の開口、裏の開口、階段、はしご、雨どい、窓、縁
     - 通るのに要るもの：なし、服、検問、鍵・カード、抜け道
   - **区域のつながりの図**：区域を点、出入り口を線にした図。画像で `investigation\party-graph.png` に保存してください。
   - **層の図**：表から奥へ、どう巻いているか。標的の30分の動きを重ねてください。
   - **チャンス3つ**
     - 筋書き
     - 舞台の区域
     - **その区域への入り方を3通り以上**（入り方ごとに、要るもの）
   - **下の「合格の基準」を、この設計の時点で満たしているかの表**
2. 平面図の下書き（階ごとの上から見た図）を `investigation\party-plan-<階>.png` に保存してください。手書きの代わりで、区域の名前と出入り口の印があれば十分です。
3. **ここで止まり、報告してください。** ユーザーが「続けて」と言ったら、作業2に進みます。

### 合格の基準（つながり）

ホテルの数字は、`investigation\map-topology.ts` で測ったものです。このスクリプトは、新しいマップも測れるように直してください（マップのファイルを引数で選べるようにする）。

| 基準 | ホテル | このマップの目標 |
|---|---|---|
| 入口が1つの区域（行き止まり） | 5（うち4つがチャンスの舞台） | チャンスの舞台は0。全体でも、物置などの小部屋だけ |
| チャンスの舞台への入り方 | 1〜2 | 3以上。そのうち少なくとも1つは、服も検問も要らない（抜け道など） |
| スタッフ区域どうしのつながり | 厨房・ランドリー・警備室は、外にしか出られない | スタッフ区域だけを通って、地下・1階・2階・屋根裏を行き来できる |
| 隣り合う階のあいだの道 | 1〜2本（階段だけ） | どの隣り合う2階のあいだにも2本以上。種類を変える（表の階段・裏の階段・抜け道） |
| 部屋の中の区切り | 大きな部屋も一室（厨房は 24m × 16m） | 15m を超える部屋は、家具や仕切りで視線を切る |
| 死体の隠し場所 | 21個（屋上は0） | どの区域からも、15m 以内に1つ以上 |
| 入口の検問 | 表の道のただ一つ | 正面に、招待状の確認か身体検査。それを避ける入り方が2つ以上 |

## 作業2：作る（ユーザーが「続けて」と言ったあと）

### 2-1. マップ

- `scripts/build-party.ts` で `src/data/party.json` を作ってください。ホテルと同じ形式にします。
- 部屋の中を区切ってください。家具・仕切り・柱で、視線が切れるようにします。
- 区域ごとの立入の例外（前の依頼で足した `allowedDisguises`）を使い、区域の決まりと、そこで働く人の服を合わせてください。

### 2-2. 抜け道の仕組み（新しい仕組み）

- 「2点のあいだを移動するつなぎ」として作ってください。
  - 種類：はしご、雨どい、窓、縁
  - データ：両端の位置、移動にかかる秒数、種類
  - Eの長押しで移動します。途中で離すと、元の位置に戻ります。
- 見られたときの扱い
  - 移動中に見られると、疑わしい行動として疑惑が上がるようにしてください。上がり方はJSONに置きます。
  - 立入禁止の場所に出た場合の扱いは、今の立入禁止と同じです。
- 動き
  - 登る・またぐ動きを付けてください。今の動きのデータ（`motions\`）と同じ作り方・同じ形式にします。
  - 最初は簡単な動きでかまいません。
- NPC はこのつなぎを使いません。

### 2-3. 人と予定

- 予定は、このマップ用の予定のファイル（例：`party-schedule.json`）に書いてください。
- 動かない人を全体の3割以下にしてください。
  - 給仕は、厨房と舞踏室のあいだを行き来する
  - 客は、グループで場所を移る
  - 警備は、巡回する
- 顔を知る人（`knowsFaces`）は、持ち場をよく考えて置いてください。ホテルのA1（セラーの入口の前に給仕長がいて、道がふさがった）のように、ただ一つの道をふさがないようにします。

### 2-4. チャンス3つ

- このマップ用のチャンスの仕組み（例：`src/party/chances.ts`）と、データ（`party-chances.json`）を作ってください。
- 完了の判定には、今の `Chances` の仕組み（出来事で手順が進む）を使ってかまいません。
- 3つのそれぞれで、設計に書いた3通り以上の入り方が、実際に歩いて通れることを確かめてください。

### 2-5. 遊べるようにする

- 入口：`app\party.html` と、その入口のコード（例：`src/party/main.ts`）を作ってください。
- ホテルの `main.ts` は大きいので、全体の作り変えはしないでください。
  - 共通にできる部分だけを、小さく取り出してかまいません。
  - 試作なので、`main.ts` を写して、このマップ用に直す形でもかまいません。どちらにしたかと理由を、報告に書いてください。
- 単体のHTMLを `outputs\m5-prototype\party-prototype.html` として作ってください（`scripts/standalone.mjs` を参考にするか、引数で入口を選べるようにする）。
- 開始の準備画面・服・持ち込み・採点・結果の画面は、ホテルと同じ流れにしてください。

## 確かめ方

- **つながり**：`map-topology.ts` で、上の「合格の基準」を測り、表にしてください。
- **歩いて確かめる**：チャンス3つ × 入り方3通り以上の、すべてのルートでテストしてください。決まりは `codex-working-guide.md` と同じです。
  - 周りの人を消さない
  - `dress()` で服を着せない
  - 瞬間移動せず、ナビの道か抜け道を歩く
  - 時間は `clock.jump` で飛ばす
  - 採点は `ScoreLedger` と `computeResult` で行う

  各ルートで、ゴーストのまま標的を倒せるかを確かめ、表にしてください。ゴーストにできないルートがあれば、理由を書いてください。
- **抜け道**：テストにしてください。
  - 長押しで向こう側へ移る
  - 途中で離すと戻る
  - 見られると疑惑が上がる
- **性能**：ヘッドレスのブラウザで、場所ごとの fps を測ってください。ホテルの `m53-fps-results.json` と同じ形にします。
- **画面**：各階と、抜け道を使っているところの画面写真を `investigation\` に保存してください。撮ったら、自分で開いて確かめてください。
- **ホテル**：`npm test` がすべて成功すること（ホテルのテストを含む）。`index.html` を作り直した場合も、ホテルが今までどおり遊べることを確かめてください。

## やらないこと

- ホテルのマップの作り直し（この試作の結果を見てから決めます）
- NPC が抜け道を使うこと、ドアの開け閉め、施錠
- 人の「仕事」の仕組み（中断と再開）や、設備の状態（構造監査の土台A・B）
- 増援の銃と、落とす銃の件
- プレイヤーが隠れる場所（クローゼットなど）
