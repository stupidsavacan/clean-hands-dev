# クラブ第2段階

[クラブを開く](../club-prototype.html)。準備画面で「探索開始」を押す。

## 作ったもの

- 一般客16人、招待客4人、投資家1人、警備5人、職員8人を配置した。
- 一般客は個人ごとの乱数で次の行き先と滞在時間を選ぶ。乱数の種を固定した。床の立ち位置と向き、踊りの位相を分けた。
- ボトル係は厨房から裏階段でVIP席へ上がる。技術係は機材室のはしごを使う。
- クロークと厨房に服を置いた。技術係・用心棒・護衛の服は、倒れた本人から **T長押し** で取得できる。収納と着替えは既存の仕組みを使う。
- 入口で **B長押し** すると検査を受けられる。ワイヤー、毒、コインは通る。銃は持ち込み不可。事務所の金庫には拾える拳銃を1丁置いた。
- クラブの増援波数を0にした。警戒度3では、最後の目撃か銃声の地点に近い警備を最大2人送る。検査役と随行護衛は応援の割り当てから外す。最後の目撃か銃声から24秒たつと応援の捜索を切り上げ、予定に戻る。
- 画面の時刻を区域名の下に離した。タブ名は「CLEAN HANDS — クラブ」。

## 確かめた結果

- 本番の移動・衝突・区域判定で30分を進めた。個別の予定370区間がすべて到着。随行護衛も投資家の8区間について到着を記録した。
- 時間切れと壁へのめり込みは0件。1秒ごとの区域確認で、職員を含め許可のない区域にいた記録は0件。
- 同じ秒に出発する一般客は最大2人。出発秒、出発区域、到着区域が同じ人数も、随行を含め最大2人。
- 移動中も1秒ごとに数えた。同じ出発区域から同じ到着区域へ向かっていた人数は最大2人。
- ボトル係は裏階段を通過。正面階段での昇降は0件。技術係のはしご移動も確認した。
- 追加した試験で、警戒度3の応援、持ち場の維持、捜索後の復帰、警備員の補充と復活が0件であることを確認した。
- ブラウザで、検査前は入口で止まり、検査後に入れた。クロークの服へ **T長押し** で着替えられた。
- `npm test` は既存分を含め316件成功。失敗0件。 `npm run check` と単体HTMLのビルドも成功。ブラウザの例外とコンソールエラーは0件。
- 予定の記録は [club-stage2-schedule-results.json](club-stage2-schedule-results.json)。試験出力は [club-stage2-tests.txt](club-stage2-tests.txt)。

## 性能

同じPCで夜会、着手前の第1段階、今回の第2段階を順に測った。

## 設計からの具体化

- 改訂済みの平面を使った。壁、階段、開口、照明の座標は維持した。服の取得場所としてクロークのロッカーを足し、厨房の既存ロッカーに収納を設定した。事務所に金庫を置いた。
- 厨房と搬入口に清掃員の許可を足した。技術足場の職員許可は技術係に限った。
- 通常客の同行グループは置かず、16人の個別予定で動かした。
- 最初の滞在だけ22〜98秒でずらした。その後は行き先ごとの滞在時間幅から選ぶ。
- 投資家はVIP席、フロア、バー、トイレを巡る。催しの動作は第3段階に残した。

## 人が遊んで確かめてほしいこと

- フロアで同じ方向を向く客や、まとまって出入りする客が目立つか。
- 入口で検査の手順が分かるか。クロークと厨房の服を見つけやすいか。
- 警備の応援が来ても、持ち場に残った警備が分かるか。
- iPad第9世代の実機で、フロアやバーへ入ったときに操作が重くならないか。
