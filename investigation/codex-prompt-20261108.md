## 4. 進め方

1. 資料の項目を一覧にし、それぞれに「できたら何が見えるか」を1行で書く。
   - 例：「アニメーションラボの◯◯で、左手が銃のスライドを引く」「クラブで E を押すと◯◯が出る」
   - 試験が通るだけでは、できたことにしない。
2. 1項目ずつ直す。
   - 1項目ごとに1コミット。メッセージは英語で、何を直したかが分かるように書く。
   - `git add` はファイル名を指定する。`git add -A` や `git add .` は使わない。
   - push はしない。確かめてから、こちらで送る。
3. 行末を変えない。
   - ファイルごとに CRLF と LF が混ざっている（例：`app/src/main.ts` は LF、多くは CRLF）。元のファイルと同じ行末で保存する。
   - コミットの前に `git diff --stat` を見て、触っていない行が大量に変わっていないか確かめる。
4. 直した項目に合わせて試験を足す。
   - 見た目や数値で決まったこと（向き・高さ・距離など）は、試験で固める。
   - 動きは `app/tests/combat-motion.test.ts` や `app/tests/visual-state.test.ts` のやり方に合わせる。
5. 決めないといけないことが出たら、勝手に決めない。
   - 案を2つまで書き、報告に入れて、その項目は止める。ほかの項目は進めてよい。
