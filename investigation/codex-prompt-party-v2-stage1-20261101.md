## 第1段階に入る前に直すこと

### 1. 階段S5が、1階の厨房と使用人室のあいだの壁を突き抜けている

- 座標表では、S5 は (17, 0, 32) から (17, 3.5, 24) へ上ります（x = 16〜18）。
- ところが1階には、厨房Kと使用人室Sのあいだに壁 W027（(14, 30)〜(20, 30)、高さ2.8m）があります。S5 は z = 30 でこの壁を横切ります。
- そのうえ、S5 の高い側の半分（z = 24〜30）は、厨房の床の上に張り出します。給仕長 W01 の立ち位置 (18, 0, 24) は、その張り出しのすぐ下です。
- 設計書の切り欠きの決まりは「S5 の S–U 境界」だけで、この K–S の壁には触れていません。設計の点検（`geometryErrors: []`）も、これを見つけていません。
- **直し方**
  - S5 を使用人室Sの中に収めるか、厨房とのつながりとして設計し直してください。
  - どちらにしたかを、設計書の差分として書いてください。
  - 給仕長の立ち位置と、厨房の人の動きも合わせて直してください。

### 2. 同じ種類の食い違いを、機械で探す

- 次の組み合わせが、同じ階や上下の階で重なっていないかを調べるスクリプトを作ってください。
  - 階段・抜け道の通り道（両端の踊り場を含む）
  - 壁・家具・隠し場所・人の立ち位置・服や道具の置き場所
- 置き場所は `investigation\party-v2-overlap.ts` です。結果を報告に載せてください。
- 重なりが0になるまで、第1段階の形を作り終えたことにしないでください。

## プレイテストの道具と合わせること

ユーザーは、プレイテストの道具（http://127.0.0.1:8795/party）で遊びます。道具は Claude が管理しているので、次の形を守ってください。

- 遊ぶファイルは `outputs\m5-prototype\party-prototype.html` のまま、第2版で置き換えてください。
  - 第1版は `party-prototype-v1.html` という名前で残してください。
- デバッグ用の入口 `window.__cleanHands` は、今と同じ名前と使い方を保ってください。
- 第3段階で作るときの決まり
  - `party-actions.json` の形（`acts` の各項目に `id`・`label`・`at`）を保つ。
  - `party-chances.json` の `window` に、そのチャンスが実際にできる時間帯を入れる。道具は、シナリオの開始時刻を `window` から決めます。

### 第1版のメモ「ほかのシナリオを選んでも、これになる」について

これは、プレイテストの道具の表示の問題でした。作戦の途中でシナリオを変えると、変わるのは次の作戦からですが、表示だけが先に変わっていました。Claude が直したので、調べなくてかまいません。

ゲーム側の「開始と同時に、チャンスが全部発見済みになる」（`chances.ts` の `afterAi()`）は、設計書のとおり第3段階で直してください。
