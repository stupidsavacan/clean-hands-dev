## 1. 決まっていること（変えない）

- **HITMAN に合わせる。** 調べて HITMAN にある動きだけを入れます。HITMAN にあるか分からない物は、調べてから決めます（段階D）。HITMAN の数値は見つからないので、距離・秒数は CLEAN HANDS 独自の値としてデータに置き、`_note` に「独自値」と書きます。
- **警備AIが先、新しいマップは後。** 新しいマップは、舞台などを利用者が決めてからです。今回は作りません。
- **目の高さと視界は触らない。** 目の高さの食い違い（しゃがんだ警備の頭が 1.1〜1.2 m の物より上に出る。視線の判定は立った時の 1.6 m のまま）は、利用者が別に報告します。`vision` の値と `perceive` の視線の作りは変えないでください。気づいた事は報告に書くだけにします。
- 遮蔽の作り（`app/src/cover-spots.ts`、`combat.ts` の `choose`・`coverStep`）と、AIラボの「戦闘」の場面を土台にします。今ある場面は通ったままにします。

## 2. 今の作り（第1段）

- 遮蔽の場所はマップから1回だけ作ります。`low`（腰〜胸の高さの物の裏でしゃがむ）と `edge`（壁の端の横に立ち、端から出て撃つ）の2種類です。クラブで248か所です。
- 撃ち合いになると、警備は空いている遮蔽のうち、エージェントから隠れていて、そこから撃てる場所を選びます。距離は `tactics.ranges` を基準にします。
- 隠れる → 覗く（立ち上がる・端から出る）→ 撃つ → 隠れる、をくり返します。隠れている間は撃ちません。
- 回り込まれて今の場所が丸見えになったら、選び直します。遮蔽がない時は、近すぎれば下がり、遠すぎれば一度に `hop`（8 m）まで詰めます。
- 姿勢は `Npc.posture`（`stand`・`cover`・`peek`）で表します。見た目は `combat-view.ts` で、しゃがみが `cover`、立ち上がりが `coverAim` です。
- 数値は `combat.json` と `club-combat.json` の `tactics` にあります。
- 視界は、14 m（屋外25 m）まで今まで通りです。その先は警備だけ2.1倍まで見えますが、遠いほど遅く気づきます。撃ち合い中の警備は60 mまで見えます。

## 3. 段階

### 段階A　3つのマップで確かめて直す

第1段はクラブでしか確かめていません。

1. ホテル・夜会・クラブで、遮蔽の場所の数と種類を出します。次のようなおかしな場所がないか、図か画像で確かめます。
   - 階段の上・水の中・歩けない所
   - 低いのに遮蔽になる物（階段の側板 `stair-cheek-*` など）
2. おかしな場所は、データの決まりで外せるようにします（例：`tactics.excludeIds` に ID の先頭を並べる）。コードに個別の ID を書きません。
3. **自分の物で隠れていない遮蔽。** 今は「その遮蔽の物では隠れていないが、たまたま遠くの別の箱で隠れている」場所も選ばれます（AIラボ「遠いと遮蔽を伝って詰める」で、木箱aの手前の場所が、8 m 先の木箱bで隠れて選ばれた）。
   - 遮蔽の物そのものがエージェントとの間にある場所を優先するか、そうでない場所は選ばないようにします。
   - どちらにしたかと、その理由を報告に書きます。
4. 増援部隊（小銃・`long`）の距離 8〜24 m が、ホテルの駐車場・搬入口で動くか確かめます。
5. 重さを測ります。警備10人が同時に撃ち合っている時の、遮蔽選びにかかる時間（1フレームあたり ms）です。重ければ、選び直しを人ごとにずらす、近くの遮蔽だけを引ける表にする、などで軽くします。
6. 各マップで、警備が隠れて撃っている画像を残します。

### 段階B　チームで役割を分ける（足止めと回り込み）

HITMAN 2 の開発者インタビューに、「協力して回り込み、追い出す」「完璧に狙える位置へ動いてから撃つ警備がいる」とあります。プレイヤーの報告でも、角で待つといずれ回り込まれます。

1. 同じ撃ち合いの警備に役割を付けます。
   - **足止め**：今の遮蔽から撃ち続けます。覗く時間を長めにします。
   - **回り込み**：エージェントの横か後ろが見える遮蔽へ、遮蔽を伝って移ります。
2. 回り込みの人数は、撃ち合いの人数で決めます。例：2〜3人なら1人、4人以上なら2人まで。数はデータに置きます。
3. 回り込みの行き先は、足止めの人から見たエージェントの向きと、十分な角度の差がある場所にします。例：60度以上。
4. エージェントが同じ遮蔽に長くいる時（例：8秒以上）に、回り込みを始めます。
5. 回り込みの人が倒れたり、遮蔽を失ったりしたら、別の人が引き継ぎます。
6. 役割は撃ち合いが終わったら消します。今ある `localResponse`（近くの警備を送る仕組み）と食い違わないようにします。
7. AIラボに場面を足します。
   - 角で待つと回り込まれる：2人の警備のうち1人が、エージェントの横が見える場所へ移る。
   - 回り込みは1人だけ：3人で1人。
   - 回り込みの人が倒れると、別の人が引き継ぐ。

### 段階C　フラッシュ（警備が投げる）

wiki では「警備は戦闘中によくフラッシュを投げる」とあります。投げる条件は見つかっていません。

1. **先に調べます。** 投げる条件、投げる人（警備全員か、一部か）、届く距離、目がくらむ時間と強さ、距離での弱まり、投げる前の合図、エージェントへの警告表示を調べます。
   - 前回、fandom の wiki は読めませんでした（402）。動画の説明や別の wiki など、ほかの出典を探してください。
   - 出典と確度を [guard-ai-policy-20261113.md](guard-ai-policy-20261113.md) の調査表と同じ形で書きます。
2. 決められなかった所は CLEAN HANDS 独自の値にします。目安は次の通りです。
   - エージェントが同じ遮蔽に長く隠れている時だけ投げる。
   - 1回の撃ち合いで1人1個まで。
   - 届くのは15 mくらいまで。
3. 壁越しや扉越しには投げません。HITMAN の不具合として報告されている所なので、真似しません。投げる線が通るかを、今の視線の箱で確かめます。
4. 当たった時の効果（ゲームの中身）を作ります。例：数秒、エージェントの照準がぶれ、警備から見えやすくなる。数値はデータに置きます。
5. **画面の表現（白く飛ぶ・警告の印）は、UI ラボだけで作ります。** ゲームの画面には入れません（`CLAUDE.md`：画面は UI ラボで仕上げて、利用者がよいと言ってから）。1080×810 と 1920×1080 の画像を残します。
6. **投げるモーション**は、モーションのラボ（`app/src/labs/motion-clips.ts` など、今のモーションと同じ所）で作ります。歩き・遮蔽のしゃがみからつながるようにします。手と投げる物が離れないこと、肘が変に曲がらないことを、試験と画像で確かめます。
7. フラッシュの物のモデルが要る時は、今の小物の作り方に合わせて作ります。HITMAN の見た目を真似しません。
8. AIラボに場面を足します。
   - 遮蔽に居座ると投げてくる。
   - 壁の向こうには投げない。
   - 1人1個まで。

### 段階D　HITMAN にあるか調べてから決める物

1. **撃たれたら下がる。** HITMAN の警備が、撃たれた後に下がったり遮蔽を変えたりするかを調べます。
   - 根拠があれば、段階A〜Cと同じやり方で入れます。
   - なければ入れずに、報告に「根拠なし」と書きます。
2. **落ちている強い銃を拾わない。** 「警備は拾わない」というプレイヤーの報告があります。今の警備は、落ちた銃を回収します（ROADMAP の「落下銃の回収」）。撃ち合いの最中に拾って使うことはしていないはずなので、確かめて報告します。変える必要がある時も、変えずに報告します。
3. **エージェントの投げ物への反応**（HITMAN の「A bird? A plane? A GRENADE!」）。CLEAN HANDS には今、エージェントが投げる爆発物がありません。入れずに、報告に「対象の物がない」と書きます。

## 4. 止まる条件

次の時は、そこで止まって報告します。次の段階へ進みません。

- ゲームの遊び方が大きく変わる決め事が要り、HITMAN にも根拠がない時。案を2つ以上書いて止まります。
- 今ある試験（AIラボの場面、`m55.test.ts`、`checkpoint-*.test.ts` など）が、新しい動きのせいで通らなくなった時。理由と案を書いて止まります。期待値をゆるめたり消したりしません。
- 目の高さ・視界の作りを変えないと進めない時。
- 段階Dが終わった時（これで最後です）。

## 5. 決まり

- 報告は日本語で、短く分かりやすく書きます。
- 頼まれた所だけを変えます。ゲームの画面は変えません（段階CはUIラボまで）。
- 作業は main ではなく、別のフォルダとブランチで行います。
  ```
  cd <ルート>
  git worktree add ../m5-guard-ai -b guard-ai/stages main
  ```
- 段階ごとに1つ以上のコミットにします。メッセージは英語で書き、末尾に `(Codex)` を付けます。**push はしません。** main にもマージしません（Claude が確かめてから入れます）。
- `git add` はファイル名を指定します。行末（CRLF・LF）を変えません。コミットの前に `git diff --stat` を見ます。
- 試験の期待値をゆるめたり消したりしません。長い試験（歩くゴースト）は回さず、`npm run test:fast` を使います。
- 作り直せるページ（index.html、club-prototype.html など）は git に入れません。`build-info.json` もコミットしません。
- **確認用サーバー（8795〜8798）は止めません。** 自分の確認には、自分のポート（8890〜8899）を使います。止まっていたら、セッションと切り離して起動します（`Start-Process python -ArgumentList 'tools/dev-servers.py' -WorkingDirectory <ルート> -WindowStyle Minimized`）。
- 決まっていないことを自分で決める時は、案を書いて報告し、いちばん無難な方で進めます。
- 利用者のメールアドレスなど個人の情報を、外部の検索や送信に入れません。
