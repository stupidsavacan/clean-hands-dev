# CLEAN HANDS M5.8 構造監査：いまのホテルで書けること・書けないこと

- 作成：2026-11-01（Claude）
- 対象：`outputs\m5-prototype\app`（`clean-hands-m5.8-pc-playtest-fixes.html` と同じ版）
- 方法：コードとデータを読み、数を数えました。ゲームは何も変えていません。
- 目的：「HITMAN比較：不足要素」の監査書（48項目）を進める前に、いまの土台が何を表せて、何を表せないかをはっきりさせます。

## 0. 結論

1. **いまのホテルは「世界のシミュレーション」ではなく「舞台装置」です。**
   - 120人のうち92人は、一歩も動きません。
   - AIの役割は3種類だけで、職業の違いは服の見た目だけです。
   - ドアや設備のように、状態を持つ物はありません。
   - 14チャンスは、42個の決め打ちの行動で動いています。
2. **不足要素の監査書の48項目は、ほぼすべて、いまない土台を前提にしています。** 土台は5つに分けられます（3章）。どれも、今のコードに少し足すだけでは作れません。
3. **2回のプレイテストで出た不具合（原因で数えて延べ20件）は、ほとんどがデータの食い違いと、決め打ちの穴でした。** 「仕組みが足りないから遊べない」という失敗は、出ていません（4章）。
4. **次にやるとよいこと**
   - まず、マップの自動点検を作ります。
   - そのあと、土台を1つずつ、狭い場所で試しながら足します（6章）。
   - 新しい中身（パーティー会場など）は、その後にします。

### 1-4. チャンスと点数

- **チャンス**：14個。
  - 手順の完了条件は、8種類の出来事のどれかです（服を着た、話した、フラグ、仕掛けの準備、倒した方法・場所など）。
  - その出来事を起こすのは、`m57.ts` の `switch` に書いた **42個の決め打ちの行動**（＋A1・A2用の `m53.ts`）です。それぞれ「この場所で・この人のそばで・この時間に、Eを長押し」と決まっています。
  - 世界の状態（誰がどこにいるか、何が起きているか）から成立を判定する仕組みはありません。
- **仕掛け**：9種類（樽・プールの照明・クレーン・シャンデリア・ガス・手すり・ボート燃料・花火・突き落とし）。どれも1回きりで、元に戻りません。
- **点数**：ゴーストを崩す6項目と、記録の消去。

### 1-5. 確かめの仕組みと性能

- **テスト**：250件。ただし、35ファイルのうち6ファイル（`ai`・`lod`・`m3`・`m4`・`playthrough`・`world`）は、練習用の `marina.json` で確かめています。検問の不具合が見逃されたのはこのためです。
- **マップの点検**：「検問で検査できるか」「線を回り込めないか」「服の持ち主はその区域に入れるか」といった、データ同士が合っているかの自動の点検はありません。
- **性能**：このPC（AMDの内蔵GPU）で、120人のとき。
  - だいたい 80〜90fps です。
  - テラスは 59fps（1秒間の最低 48fps）、樽を仕込んだあとの地下セラーは 70fps（最低 49fps）です。
  - **iPad 第9世代では測っていません。**

## 2. 書けること・書けないこと

| 作りたいもの | いまの土台で | 理由 |
|---|---|---|
| 新しい部屋・区域・階段 | **書ける** | `build-hotel.ts` に箱を足すだけ。ただし手書きなので、食い違いは人が遊ぶまで分からない |
| 新しいチャンス（決め打ち） | **書ける** | `m57.ts` に case を足し、`chances.json` に手順を書く。1つにつき、場所・人・時間・セリフ・予定の上書きを手で合わせる |
| 新しい予定・セリフ | **書ける** | `schedule.json`・`dialogue.json` |
| 区域ごとの立入の例外 | 書けない | 表が「服 × 区域の種類」だけ（漁師の不具合の原因） |
| 職業ごとに違う反応 | 書けない | AIの役割が3種類だけ |
| 人が仕事を中断して、あとで戻る | 書けない | 予定は時刻で決まる固定の表で、「やりかけの仕事」がない |
| 落ちた物に人が気づく・拾う | 書けない | 人は床の物を見ていない |
| ドア・窓の開け閉め、施錠 | 書けない | ドアの物がない。部屋の出入り口は壁の開口 |
| はしご・乗り越え・縁の移動 | 書けない | 上下の移動は階段4本だけ。プレイヤーの動きに登る・乗り越える仕組みがない |
| 設備の状態（電源・水・ラジオ） | 書けない | 状態を持つ物の仕組みがない。仕掛けは1回きり |
| 同じ結果を別の手順で（チャンスの代わりの成立） | 書けない | チャンスは、決め打ちの行動が出す出来事でしか進まない |
| プレイヤーが隠れる | 書けない | 隠し場所は死体用だけ |
| セーブ・チャレンジ・任務作成 | 書けない | 仕組みがない |

## 3. 不足要素の監査書（48項目）と、必要な土台

48項目を、必要な土台で5つに分けました。「いま」の欄は、コードで確かめた状態です。

### 土台A：人の「仕事」（職業・作業・中断・再開）

- **対象**
  - NPCの反応・職務AI：#1〜12 のほぼすべて
  - 社会的ステルス：#35〜38
- **いま**
  - 一部ある：#2（目撃者が警備員へ通報する。ただし違法な行為と死体だけ）、#38（無線で警備員が集まる。警戒度2・3で標的が避難部屋へ移る）、#11（バレた服だけを覚える）
  - ない：残りすべて
- **作るもの**
  - 職業ごとの役割
  - 仕事の一覧（どこで、何を、どれくらいの時間）
  - 担当の割り当て
  - 中断と再開
  - 時間割を「仕事の列」に置き換える
- **規模**：大。`ai.ts`（194行）と予定の仕組みの作り直しに近い。性能への影響も大きい。

### 土台B：状態を持つ物・設備

- **対象**：#5、#13〜19、#22〜26
- **いま**
  - 一部ある：#4（コインの音で人が見に来る。拾わない）、#24（スパナはあるが、決まった場所でしか使えない）
  - ない：残りすべて
- **作るもの**
  - 物の状態（動いている・止まっている・壊れている・汚れている）
  - 人がそれに気づく仕組み
  - 元に戻る仕組み
- **規模**：中〜大。土台Aがないと「気づいた人が対応する」ができないので、効果は半分になる。

### 土台C：空間のつながりの変化

- **対象**：#20・21（ドア・施錠）、#27〜30（乗り越え・窓・はしご・縁）、#34（近道）
- **いま**
  - ドア・窓・はしごは、ない。
  - 検問の線（2か所）だけが、通れる・通れないを切り替える。
- **作るもの**
  - ドアの物
  - 開け閉めでナビの道が変わる仕組み
  - プレイヤーの登る・乗り越える動き（モーションを含む）
- **規模**：中。ナビは0.5m格子なので、道の切り替えはできそう。プレイヤーの動きは、モーションを作る手間が大きい。

### 土台D：世界の状態でチャンスを判定する

- **対象**：#37・39・40
- **いま**：ない。42個の決め打ちの行動だけ。
- **作るもの**
  - チャンスの成立条件を、出来事ではなく状態で書けるようにする（例：「標的がグラスの前にいて、出されたのが毒入り」）
- **規模**：中。ただし、判定に使える「状態」は土台A・Bが作るので、それより先には意味が出ない。

### 土台E：遊び方の外側（見せ方・繰り返し）

- **対象**：#31〜33（物陰・人混み・隠れ場所）、#41〜48
- **いま**
  - 一部ある：
    - #32（人混みに混じる：15か所と、人数で見つかりにくくなる仕組み）
    - #42（できない理由の表示：「この服では入れない」「致死毒がない」など一部）
    - #44（持ち込みの選択：道具2種と銃）
    - #45（開始地点3つ。2つは閉じたまま）
  - ない：残り
- **規模**：小〜中。ほかの土台に頼らないものが多い。
  - #33 プレイヤーの隠れ場所
  - #42 理由の表示の徹底
  - #43 セーブ
  - #45 開始地点の解放

  この4つは、今の土台のままでも作れます。

## 4. プレイテストで出た不具合の内訳

2回のプレイテスト（2026-10-31）で直した・直す予定の不具合を、原因で分けました。1つの不具合に原因が2つあるもの（A1の給仕長：持ち場の位置と6秒の猶予）は、それぞれに数えたので、延べ20件です。

| 原因 | 件数 | 例 |
|---|---:|---|
| マップのデータの食い違い | 7 | 検問2か所で検査できない、検問の脇の隙間、服の置き場所が丸見え、屋上に隠し場所がない、漁師の服で事務所に入れない、給仕長の持ち場がセラーの入口の前、A4・B4で一人になる時間がない |
| 決め打ちの穴 | 4 | 非常ベルで全員が避難、シャンデリアの巻き添え、目撃者の通報のループ、挨拶のあと6秒で見抜かれる |
| 見た目 | 5 | Tポーズ、浮く銃、残るコイン、銃を持ったしゃがみ、増援の銃と落とす銃 |
| 操作・説明 | 3 | Rで確認なしにやり直し、A1の手順に時刻と場所がない、検問の表示が誤り |
| B3の付き添い（護衛の待機場所が決まっていない） | 1 | |

- **いちばん多いのは、データの食い違いです。** 手で書いた座標同士（警備員の位置と線、手すりと線、服と区域の表）が合っていませんでした。どれも、人が遊ぶまで誰も気づいていません。
- **「仕組みが足りないから遊べない」という失敗は、出ていません。** 遊んだ人の不満の中心は、「決められた手順が、実際には通れない」でした。

## 5. いまの作りの限界

1. **手書きの座標が増えるほど、食い違いが増える。** マップを広げる・部屋を足すたびに、今回のような不具合が出ます。自動の点検がないので、見つけるのは人が遊んだときです。
2. **立っているだけの人が多い。** 92人が一歩も動かないので、時間がたってもホテルの様子が変わりません。観察して計画を立てる遊びの材料が少ない状態です。
3. **チャンスを1つ足す手間が大きい。** 場所・人・時間・セリフ・予定の上書き・表示・テストを、毎回手で合わせます。決め打ちなので、遊ぶ人が考えた別の解き方は成立しません。
4. **性能の余裕が分からない。** このPCでも、テラスで 48fps まで落ちます。土台Aで人に仕事を持たせると、計算が増えます。iPad 第9世代では、まだ測っていません。
5. **確かめが練習用マップに寄っている。** 6つのテストファイルが `marina.json` を使っています。

## 6. 進め方の提案

| 段階 | やること | 終わりの条件 | 規模 |
|---|---|---|---|
| 0 | 今の修正（プレイテスト2回目の依頼） | 依頼の9項目が直り、テストが通る | 依頼済み |
| 1 | **マップの自動点検** | 本番のホテルで、毎回テストとして次を確かめる：すべての検問で検査が成立し、線を回り込めない／服の持ち主がその区域に入れる／14チャンスを歩いてゴーストで終えられる／隠し場所まで見られずに運べる／服の置き場所が人から見えない | 中 |
| 2 | **性能の測定** | iPad 第9世代（横持ち）で、場所ごとの fps を測る。人に仕事を持たせる余裕があるかを決める | 小 |
| 3 | **小さな土台** | 区域ごとの立入の例外、プレイヤーの隠れ場所（#33）、できない理由の表示の徹底（#42）、閉じている開始地点の解放（#45） | 小〜中 |
| 4 | **土台Aの試作を、1か所だけで** | たとえばバーとランドリーの周りで、立っている人に仕事を持たせ、監査書の連鎖C（漏水 → 清掃 → 人の流れ → 予定の遅れ）を最後まで作る。プレイテストの道具で、面白いかを確かめる | 大 |
| 5 | 4が面白ければ、土台A・Bをホテル全体へ。そのあと土台C・D | 一部のチャンスが、決め打ちの手順以外でも成立する | 大 |
| 6 | 中身を足す | パーティー会場、増援の銃、セーブ、チャレンジなど | 中 |

- **段階1を先にする理由**：どの段階でもマップを変えます。点検がないまま変えると、今回と同じ種類の不具合がまた出ます。点検は、今回作った調査スクリプト（`checkpoint-*.ts`、`ghost-walk.ts`）を広げれば作れます。
- **段階4を1か所で試す理由**：土台Aは作り直しが大きく、性能にも響きます。ホテル全体に入れる前に、本当に面白くなるかを、狭い場所で確かめるべきです。

## 7. 決めてほしいこと

1. **このゲームの軸**
   - 決め打ちのチャンスを磨く（今の延長）
   - 人と物が連鎖して動く世界を作る（監査書の方向）

   後者なら、段階4から先は大きな作り直しになります。両方を狙う場合も、どちらを先にするかを決める必要があります。
2. **段階1（マップの自動点検）を、次のCodexへの依頼にするか。**
3. **パーティー会場は、どちらの方式で作るか。**
   - 今の決め打ち方式で作る（早い）
   - 土台ができてから作る（あとで作り直しが少ない）
4. **iPad 第9世代での性能を、どこまで優先するか。** 人に仕事を持たせる規模が、これで決まります。

## 付録：数え方

- 人の数・役割・動き：`hotel.json` の `npcs` の `role`・`outfit`・`route` の長さ
- 予定：`schedule.json` の `actors`（33人）と `plan` の `do`
- 決め打ちの行動：`m57.ts` の `case` の数（42）
- 気づくもの：`ai.ts` の `perceive`・`hear`、`m3.ts` の `discover`。床の物（`detection.ts` の `floor`）を参照しているのは、プレイヤーの拾う操作だけ
- 性能：`outputs\m5-prototype\m53-fps-results.json`（このPC、ヘッドレス、120人）
- 練習用マップを使うテスト：`app\tests` のうち `marina.json` を読む6ファイル
