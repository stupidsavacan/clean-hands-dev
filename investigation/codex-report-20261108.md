# CLEAN HANDS 修正報告（第1回）

添付2資料は旧コミットの比較・監査として使い、現行コードと既存の決めを優先した。最初の対象は監査で最優先に挙がっている気絶者の救助。

| 監査項目 | できたら何が見えるか |
|---|---|
| A04・E08 担当と応援 | 1人の警備が気絶者の横に向かい、ほかの警備は現場を調べる。 |
| A05・A06・G06 救助 | 警備が身をかがめて手を添え、気絶者が起き上がる。 |
| A07・A08 復帰 | 起きたNPCが行動を再開し、気絶する前に知っていた情報を持ち続ける。 |
| A09・E09 中断と引継ぎ | 担当が行動不能になると救助が止まり、別の警備が担当できる。 |

## 気絶者の救助

| 欄 | 内容 |
|---|---|
| やったこと | `body-rescue.ts` と `m3.ts` で担当予約・接近・引継ぎ・復帰を実装。市民は既存の通報経路で警備に知らせる。 `motion.ts` と `rescue-pose.ts` で警備と気絶者の動きを同期し、ラボとゲームで共用する。救助の尺は2.4秒とした。 |
| 確かめたこと | `body-rescue.test.ts` で担当の重複防止、知識の保持、担当交代、運搬中の中断、市民の通報、死亡・隠された人の除外、開始・終了姿勢を確認。クラブでデバッグ用にNPCを配置し、発見から救助・行動復帰まで実行。ブラウザの未処理エラー0件。 |
| 確かめていないこと | iPad実機、ホテルと夜会でのブラウザ実演、別階からの救助到着、通常プレイの全経路。 |
| 止めたこと | 所持品UIの本体統合はHD10の承認待ち。落とし物の保管は、既存の配置表に保管先がないため保留。案は地図ごとの警備保管庫か、担当の職種ごとの保管先。その他の監査項目は次回以降。 |
