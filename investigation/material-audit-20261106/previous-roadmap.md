# CLEAN HANDS 開発ロードマップ

更新日：2026年11月6日。添付3資料とローカルの実装・修正記録を照合して作成。

**進める順番：現行版を確認 → AIを仕上げる → 道具で遊べるようにする → 制作済みの銃を組み込む → 動き・既存マップを整える → PC・iPadで通して確かめる。**

当面の到達点は、クラブで「潜入・道具の入手・陽動・排除・隠蔽・脱出」が一通り成立する検証版。
ホテル・夜会では、共有部分の変更による不具合が出ていないことを確認する。
日程は作業時間が未確定のため固定しない。各段階の完了条件を満たして次へ進む。

## 2. 段階ごとの計画

| 段階 | 優先度 | 到達点 | 主な作業 | 次へ進む条件 |
|---|---|---|---|---|
| M0 現行版の確認 | 最優先 | どの版を直し、どの版を遊んでいるか分かる | ソース・データ・HTMLの対応、テスト、最低限のAI記録、再現条件の固定 | 再現手順と記録から同じ現象を追える |
| M1 AIの仕上げ | 高 | 見聞きした情報に応じて警備が反応する | 目撃と音の区別、戦闘記憶、応援人数・持ち場・階の扱い | 犯人不明の調査と、犯人を知った追跡・戦闘が混同されない |
| M2 道具・投擲・近接 | 高 | クラブで道具を使う攻略が成立する | 道具配置、拾う・持つ・置く・投げる、鈍器と刃物の反応 | 道具を使った1経路で、入手から脱出・採点まで通る |
| M3 制作済みの銃の組込 | 中 | モデルと実際の武器性能が対応する | 武器定義、手と床の表示、装備選択、NPC装備、射撃・装填 | 採用する各武器の取得・使用・破棄・反応を確認できる |
| M4 動き・既存マップの整備 | 中 | 新機能を使う場面が自然に見え、既存経路も成立する | 仕草、小道具、必要なマップ反映、経路の再確認 | 見た目の破綻がなく、変更が届く範囲を明示できる |
| M5 通しプレイ・実機確認 | 中 | 次の検証版を安心して渡せる | PCとiPad、30分通し、記録、性能、配布物・説明の一致 | 通しプレイが成立し、残る問題と対象版が明記される |

M0からM5を順に進める。M2以降も、影響するAI・経路の確認はその作業の中で行う。
M5まで検証を先送りしない。

### M0：現行版の確認

- [ ] **BASE-01 対象版を固定する。** 当面の新機能の検証先をクラブにする。ホテルはAI不具合の再現先として残す。ソース、生成データ、各HTMLのハッシュと作成日時を保存する。
- [ ] **BASE-02 現行の確認結果を残す。** 型検査、既存テスト、AI実験を実行する。ホテル・夜会の通し経路は、除外した場合もその範囲を記録する。各ページが作戦開始まで動くかも確認する。
- [ ] **TRACE-01 AI判断を記録に残す。** 既存の `Knowledge`・AIデバッグ情報を使う。事件、見た人、視覚／音／報告、犯人特定の有無、状態の前後、変更理由、送信元、対象版をF8記録から追えるようにする。
- [ ] **BASE-03 ホテルのB事件を再確認する。** 実際に消音銃を撃つ試験と、遺体発見だけを起こす試験を分ける。位置・装備・時刻・乱数条件を記録する。

完了の証拠：対象版の一覧、チェック結果、B事件の再現記録。
録画の被弾2発を敵の発射2発とは数えない。元録画の未特定の警備員1人は、個体の特定が必要になった場合の調査に残す。

### M1：AIの仕上げ

前提：M0の再現と記録が使えること。

- [ ] **AI-01 既存修正を本番マップで確認する。** 戦闘中の無線、同じ遺体の再報告、屋内境界、現場の見回しを確認する。再現した不具合だけを修正する。
- [ ] **AI-02 事件と犯人を区別する。** 遺体のみ、銃声のみ、格闘音のみ、直接の殺害目撃、市民からの通報を分ける。情報が新しいか、誰から届いたかも判断に使う。既存の記憶を全面的に作り直すことは前提にしない。
- [ ] **AI-03 応援の仕様を決めて実装する。** 通報が届くことと、現場へ出動することを分ける。人数、担当区域、階、残す持ち場を設定で決める。上下階の移動自体は不具合と断定しない。
- [ ] **AI-04 見失い・再発見を確認する。** 重大犯罪で犯人が判明した警備と、音しか知らない警備を区別する。見失い直後に犯人情報まで消えないか確認する。

応援仕様のたたき台：通常の異変は近い巡回員から少人数を選び、検問・護衛の持ち場を優先する。重大事件は応援を増やす。人数や別階の参加条件は、実装前に仕様表で確定する。この案は未採用。

完了の証拠：遺体・音・直接目撃・市民通報・見失い／再発見の各記録。通常の立入違反では警告・退去が成立することも確認する。
視野角や命中率を一律に上げる調整は、ここで判断の不整合を解消してから検討する。

### M2：道具・投擲・近接

前提：M1の目撃・通報・戦闘への接続が確認できること。

- [ ] **ITEM-01 代表的な道具を配置する。** クラブの場所と職種に合う配置を決める。最初は既存モデルのハンマー・包丁・レンガなど少数でよい。生成元からデータへ反映する。
- [ ] **ITEM-02 入手と携行を通す。** 拾う、持ち替える、置く、再取得する。手にある1つと警備から見える物が一致するか確認する。変装ごとの合法性も確認する。
- [ ] **ITEM-03 コイン以外を投げる。** 狙い、飛行、遮蔽、命中、着地、回収をつなぐ。鈍器の気絶と刃物の致死を区別し、音と目撃をAIへ渡す。
- [ ] **ITEM-04 近接武器をつなぐ。** 鈍器・刃物での攻撃と、受ける側の動き、倒れる場所、身体の運搬・収納、採点まで確認する。

完了の証拠：「道具を拾う → 陽動または攻撃 → 目撃を避ける／対応する → 隠す → 脱出」の通し記録を1経路以上残す。周囲のNPCと検問を残して行う。
この段階ではモデルの数を増やすより、既存モデルが攻略に使えることを優先する。

### M3：制作済みの銃の組込

前提：M2の携行・入手の処理が安定していること。

- [ ] **GUN-01 台帳を分ける。** CSVの行ごとに「モデル割当」「モデル検証」「武器定義」「動作」「配置／初期装備／装備選択」「プレイ確認」を別の状態で管理する。色違いを別の機能として数えない。
- [ ] **GUN-02 通常の銃から少数ずつ組み込む。** 代表モデルを1種選び、定義・手・床・銃口・握り位置・NPCの落とす銃まで通す。その後、小型SMG、ショットガン、狙撃銃などへ広げる。
- [ ] **GUN-03 固有の動作を実装する。** 散弾、連射、狙撃、ダーツ効果など、採用する武器に必要な違いを実装する。鎮静・催吐・治療を同じ見た目だけで実装済みにしない。
- [ ] **GUN-04 入手経路を決める。** NPC所持、マップ配置、標準初期装備、開始前の選択を分ける。モデルがある銃をすべて初期装備へ追加することはしない。

完了の証拠：採用した各武器の読み込み、手と床の表示、射撃・装填、射程、NPC反応、検問、やり直しを確認した一覧。
制作済みの主な8種は `compact_smg`、`shotgun`、`shotgun_short`、`sniper_rifle`、`revolver`、`tranq_pistol`、`machine_pistol`、`hunting_rifle`。採用順は機能の準備状況で決める。

### M4：動き・既存マップの整備

- [ ] **VIEW-01 18の仕草を実際の場面で確認する。** 電話と耳、グラスと口、トレイの水平、作業と机の位置を確認する。手首・指の向きは目立つ場面から直す。
- [ ] **VIEW-02 座る・読む動きを整える。** クラブの座り、夜会の読書を確認する。椅子との接触、立つ／座る切り替えを含める。立ち机は必要な作業地点へ配置する。
- [ ] **MAP-01 反映する範囲を決める。** 共有AI・共有描画・共通エンジンの変更を区別する。ホテル・夜会で必要な新機能があれば、その範囲で移植または共通化する。全面移行は前提にしない。
- [ ] **MAP-02 既存経路を再確認する。** ホテルと夜会の対象経路、群衆、警備の予定、変装、採点を確認する。夜会の古い不合格記述など、現在と食い違う案内を整理する。

完了の証拠：実際のマップでの動きの確認、反映先の一覧、影響する経路の結果。
姿勢の一覧画像だけで、ゲーム内の動きまで確認済みとは扱わない。

### M5：通しプレイ・実機確認

- [ ] **QA-01 PCで通常操作の通し確認をする。** 開始、潜入、道具・武器、変装、目撃、戦闘、脱出、リザルト、やり直しまで確認する。30分の予定進行も確認する。
- [ ] **QA-02 iPad第9世代・横持ちで確認する。** タッチ操作、表示の読みやすさ、読み込み、フレーム時間、長時間プレイを実機で確認する。PCの画面サイズ変更による結果とは分ける。
- [ ] **QA-03 検証版をまとめる。** 対象ソース・データから各HTMLを再生成し、開始確認とエラー確認を行う。README、対象版、既知の問題、次回確認事項をそろえる。

完了の証拠：PCの通し記録、iPad実機の記録、配布物との対応表。
iPad実機を使えない間は、PCで確認できた範囲までを完了とし、実機確認は未完了のまま明記する。
公開は別の作業として扱う。

## 3. 後続の候補

M0〜M5の検証版が成立したあと、遊びの幅を増やすものから選ぶ。

| 候補 | 着手する理由・前提 |
|---|---|
| ブリーフケース・工具箱 | 収納と取り出し、持込、長物の隠蔽を一連の仕様にする。モデル制作だけでは完了しない |
| 未割当28行のモデル | 近接・投擲17行、ケース2行、拳銃7行、ワイヤー代替2行。共用可能な形を整理し、使う物から制作する |
| バナナ・雪玉・特殊ダーツなど | 転倒、消失、効果の違いを先に定義する。通常の投擲・効果処理が完成してから |
| 弾着への反応 | 発砲音と別の情報として扱う。既存の情報伝達と記録に接続する |
| 戦闘中の遮蔽物・位置変更 | AIの判断と記憶が安定したあと、反撃の手応えを見て追加する |
| 色違い・装飾 | 採用済みの基本モデルと動作を再利用する |
| 新マップ、スマートフォン縦持ち | 現在のマップとiPad横持ちで一通り遊べる状態になってから検討する |

28行は28個の独立した新規形状を意味しない。166行のモデル割当も、166種類の武器がゲーム内で使えることを意味しない。

## 4. 直近の着手順と管理方法

**最初に行うのは BASE-01 と BASE-02。対象版と現在の確認結果を固定する。**

1. 対象版の対応表と、現行テスト・AI実験の結果を作る。
2. TRACE-01で判断理由を追えるようにし、BASE-03でホテルのB事件を再確認する。
3. 結果を見てAI-01から進める。未再現の過去不具合を推測で直さない。

同時に進める主作業は1つにする。次の候補は2つまでにする。
新しい要望は後続候補へ追記し、進行中の段階を増やさない。
各タスクを終えるときは、この文書のチェックと、結果を示す記録へのリンクを更新する。
不具合が再発した場合は、その影響を受ける段階の完了判定を見直す。
