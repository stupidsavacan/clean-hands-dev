# CLEAN HANDS M5.8 — HITMAN比較：不足要素が生み出すゲームプレイ

> 対象：M5.8ホテル。**現状**は提供された実装監査MDに基づく静的確認、**追加後**は設計提案。未実装の連鎖を現行機能と混同しない。
>
> 記法：**追加要素 → NPC・世界の一次反応 → 持ち場・予定・区域に生じる二次変化 → プレイヤーに新しく成立する選択肢**。

## 1. NPCの反応・職務AI（1〜12）

| # | 追加要素 | 何が起こり、その先に何ができるか |
|---:|---|---|
| 1 | 床の落とし物を認識 | 銃などの放置物を発見 → NPCが確認 → 巡回・通常業務が中断 → **通常と異なるタイミングで区域を探索・移動できる**。 |
| 2 | 一般客から警備員への通報 | 一般客が不審物を発見 → 警備員への報告を試みる → 客と警備員の両方が移動 → **周囲の人員配置が連鎖的に変わる**。 |
| 3 | 警備員による回収・保管 | 警備員が落下物を回収 → 保管先まで運ぶ → 調査直後にも元の持ち場へ戻らない → **巡回ルートと警備室周辺の交通が一時的に変化する**。 |
| 4 | コイン等を拾う行動 | 音に反応 → NPCがコインを確認・回収 → 設置物が消費される／NPCの作業時間が生じる → **同じ誘導の反復を避け、物資の使い方を考える必要がある**。 |
| 5 | 設備の異常発見 | NPCが故障・漏水を発見 → 利用停止・報告・作業開始に分岐 → 設備利用者の予定に波及 → **専用イベント以外からも世界の予定を変えられる**。 |
| 6 | 清掃員の汎用業務 | 清掃対象が発生 → 清掃員が担当区域を離れる → 元の担当区画の人員減少・作業地点の人員増加 → **区域の人口と視線が時間的に変化する**。 |
| 7 | 修理の依頼・引継ぎ | 従業員が故障を報告 → 修理役が移動・対応 → 設備が停止し関連業務が遅れる → **復旧までの時間を利用して別のイベントへつなげられる**。 |
| 8 | 業務復帰 | 対応完了 → NPCが保留していた元の仕事に復帰 → 一時的な変化が終わる → **持続時間を観察し、限られた時間内の移動・操作を選ぶ**。 |
| 9 | 複数事件の優先順位 | 漏水対応中に別の重大事態 → 対応中の仕事を中断・再割当 → 異常同士が競合 → **複数の出来事の順序でNPCの行動が変わる**。 |
| 10 | 担当者の予約・引継ぎ | 1つの問題に適切な担当者を割当 → 全員が同じ場所に集中しない → 異常の場所・役割で担当が変わる → **誰が動くかを推測でき、状況に応じて工夫できる**。 |
| 11 | 異常に関する記憶 | 一度確認した事象をNPCが覚える → 再発・再確認時の反応が変わる → 単純な同一誘導が万能でなくなる → **異なる場所や物を使う試行錯誤が生まれる**。 |
| 12 | 職業別の応答規則 | 同じ漏水に清掃員は対応、客は迂回、警備員は条件付き確認 → 異なる職種が異なる場所へ動く → **どこで発生させ、誰に見つけてもらうかが選択になる**。 |

**現行との接続点**：既にあるNPCの視認・音反応、`dp`・`up`、通報・無線、スケジュール`Om`、床アイテム`cg`と銃系`dh`を利用。ただし床物体の汎用的な発見〜回収〜保管や職務別タスク管理は新設が必要。

| 23 | 小道具の自由設置 | 任意の場所に物を残す → 後からNPCが発見 → 確認・片付け・報告に分岐 → **自分が別の場所にいる間にも出来事が進行する**。 |

| 25 | 同じ設備への複数操作 | プレイヤー・スタッフが同じ設備状態を変更 → 同一結果を別経路から生み出す → **固定ボタン列ではなく、世界の状態を目的に行動を組み合わせられる**。 |
| 26 | 設備の復旧・再利用 | NPCが問題を解消 → 設備が通常状態へ復帰 → 別のタイミングでも再度作用する → **使い捨てではない、反復可能なシステム的ギミックになる**。 |

## 6. 複合ギミック：一歩先まで連鎖させる3例

### A. 放置された物 → 職務変更 → 別区域の状態変化

**#1 + #2 + #3 + #8 + #38**

1. NPCが放置物に気づく。
2. 客なら報告、警備員なら確認・回収を担当。
3. 回収担当者が通常巡回を中断し、保管場所へ移動する。
4. もとの区域では巡回間隔が変わり、移動先では人通りが増える。
5. プレイヤーは変わったNPC配置を観察し、通常とは違う探索・移動順序を選べる。
6. 対応が完了すれば通常巡回へ復帰。状況によっては別の警備員に仕事が割り振られる。

**新しく生まれる遊び**：誘導アイテムそのものではなく、**報告・運搬・帰還という一連の職務行動**が攻略計画の対象になる。

### B. 停電 → 給仕遅延 → 試飲会の状況変化

**#18 + #19 + #35 + #36 + #37 + #39**

1. バーの設備が停止する。
2. 給仕担当が対応に回り、サービスが遅れる。
3. 代役が入るか、客・ワイン商人が待機する。
4. 待機時間・サービス再開状況により、試飲会の開始や場所が変わる。
5. 適切な給仕の変装をしたプレイヤーも、代役としてサービスへ参加できる。
6. 元の専用チャンスに限定されず、**サービスが成立したという世界状態**からイベントを進行可能にする。

**新しく生まれる遊び**：「試飲会を始める専用ボタン」ではなく、**営業状態を操作した結果として試飲会の内容が変わる**。

### C. 漏水 → 清掃 → 人流変化 → 別の予定へ影響

**#6 + #12 + #13 + #14 + #20 + #26 + #36**

1. ランドリーまたはバー近くのシンクが溢れる。
2. 発見したNPCの職業により、清掃・報告・迂回へ反応が分かれる。
3. 清掃員が作業し、一部の通路が使いにくくなる。
4. NPCの経路と到着時刻が変わり、別の業務が遅延する。
5. サービスの遅れに対して、別のスタッフ・客が行動を変更する。
6. 清掃完了後、通路は通常状態へ。別の時間帯なら同じ漏水でも違う結果になる。

**新しく生まれる遊び**：シンクは「そこにNPCを1人呼ぶ装置」ではなく、**ホテルの人流・仕事・予定を変える装置**になる。

## 7. 実装順：変化がゲーム全体に広がる順

| 段階 | 実装する共通機構 | 完成条件 |
|---|---|---|
| **P0** | 物・設備の異常検知、事件台帳 | NPCが床アイテムを発見し、同じ異常を重複処理せずに記録できる。 |
| **P0** | 職種別の対応方針、担当者予約 | 客は報告、警備員は回収、清掃員は清掃、という反応が同じ仕組みから出る。 |
| **P0** | 割込み・再開・失敗時の引継ぎ | NPCは対応後に元の予定へ戻り、到達不能・別事件発生時にも破綻しない。 |
| **P1** | 汎用`WorldProp`と持続的状態 | シンク・ラジオ・電源・ドアなどが、操作→異常→NPC対応→復旧の共通規則で動く。 |
| **P1** | NPCの予定・サービスの連動 | 担当者が不在なら待機・代役が発生し、目標人物の予定が変化する。 |
| **P1** | 既存14チャンスの条件見直し | 少なくとも一部のチャンスに、専用操作順序以外からの成立方法が生まれる。 |
| **P2** | 窓・乗越え・ドア・ショートカット | 既存4階層の空間に新しい移動方法が成立し、NPCの経路にも反映される。 |
| **P3** | セーブ、解放、チャレンジ、Contracts型 | 汎用ルールが安定した後に、繰り返し遊ぶ仕組みを拡張する。 |

### 共通アーキテクチャで必須の4条件

1. **検知**：NPCが「落下物」「水漏れ」「故障」などの意味を認識する。
2. **担当**：職業・距離・緊急度・現在の仕事を踏まえて対応者を決める。
3. **割込みと復帰**：予定行動を中断して対応し、完了・失敗・引継ぎの後に正しく復帰する。
4. **波及**：NPCの移動だけで終えず、サービス・設備・通路・ターゲット予定・チャンス達成条件へ結果を渡す。

**設計上の合格基準**：同じNPCを、コインの音、放置物、漏水、故障の**異なる原因から動かせる**だけでは不十分。そのNPCが離れたことで仕事が中断し、別のNPCが反応し、ターゲットの予定や通路利用に影響し、プレイヤーが次の選択をできるまでつながって初めて、HITMAN型の複数解法に近づく。
