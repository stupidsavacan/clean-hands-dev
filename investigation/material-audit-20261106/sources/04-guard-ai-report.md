# 原作HITMANの警備員の挙動 — 調査報告書

- **対象**：『HITMAN』（2016）、『HITMAN 2』、『HITMAN 3』／『HITMAN World of Assassination』
- **作成日**：2026年11月4日
- **用途**：CLEAN HANDSのNPC行動・警戒・戦闘システムを見直すための参照仕様
- **調査方法**：公式ゲームマニュアル、ゲームコミュニティ資料、CLEAN HANDSの既存TypeScript調査結果を照合。実機での全条件再検証は未実施。

## 1. 要約

原作の警備員は、単なる「発見＝発砲」ではなく、**何が起きたか／犯人を誰だと知っているか／そのNPCが何の役割か**によって反応を切り替える。

- 一般的な立入禁止区域への侵入では、警告・退去誘導が基本。
- 犯人を特定できない遺体発見や銃声では、調査・捜索が基本。近くにいる47を自動的に犯人とみなすわけではない。
- **警備員が47の重大な暴力行為を直接目撃した場合、戦闘に移り得る。** 重大犯罪の直接目撃を、単なる無限追跡・鬼ごっこだけで処理する設計ではない。ただし犯罪の種類や拘束演出、NPCの反応状況によって例外・中間段階があり、「すべての目撃＝必ず瞬時に発砲」とは断定しない。
- 戦闘状態（Combat）では、対象を再発見すると発砲する。視線が途切れるとHuntedなどへ戻る。

## 2. 警戒状態の正式区分

原作『HITMAN』（2016）の公式マニュアルには次の状態が定義されている。これは後続のWorld of Assassination作品群の基本構造を理解する基準になる。

| 状態 | 意味 | 警備員の基本反応 |
|---|---|---|
| **Searching** | 事件・異変を把握しているが犯人は未特定 | 現場の調査、捜索 |
| **Unconscious Witness** | 47を特定できる目撃者が意識を失っている | 目撃者の扱いに応じ状態が変化 |
| **Compromised** | 47を識別できる目撃者が存在する | 身元・変装が危険な状態 |
| **Hunted** | 警備員が47の特徴を把握して追跡中 | 捜索・追跡。常時発砲状態とは異なる |
| **Combat** | 警備員が47を交戦対象として認識 | 視認時に攻撃。視認が途切れるとHuntedへ移ることがある |

**補足**：`Arresting`（拘束・投降要求）は、上記5種類とは別の具体的なNPC行動・通知として捉えるのが適切。

## 3. 状況別の反応

| 発生条件 | 原作での代表的反応 | 注意点 |
|---|---|---|
| 通常の制限区域（Trespassing）で見つかる | 警告し、区域外へ誘導 | 従えば戦闘にならないことがある |
| 敵対区域（Hostile Area）で見つかる | 厳しい敵対反応、Combatへ移行し得る | 通常の立入違反と区別する |
| 変装を見破れるエンフォーサーに見つかる | 疑念上昇、身元確認、追跡など | 単なる視認だけで必ず射撃するわけではない |
| 禁止装備・明確な違法行為を見られる | 警戒、通報、拘束、条件次第で戦闘 | 変装・行為内容・抵抗の有無によって異なる |
| **警備員が重大な暴力行為を直接目撃する** | **47を犯人として特定し、Combatへ移行し得る** | 拘束の中間段階など例外を考慮 |
| 一般市民が犯罪を直接目撃する | 逃走・通報、警備員へ情報が伝達される | 市民自身が武装警備員と同じ戦闘をするわけではない |
| 遺体・意識のないNPCを発見する | 周辺警戒、通報、捜索 | **犯人を直接識別したことにはならない** |
| 銃声だけを聞く | 発生場所を調査（Gunshot Heard） | 音を聞いただけで47の位置・犯人性が確定するわけではない |
| 弾着だけを認識する | 弾着位置付近を調査（Bullet Impact Noticed） | 発砲者の識別とは別 |
| 近接アクションの音を聞く | 異変の調査（Close Combat Heard） | 見えない犯人を無条件に特定しない |
| Combat中に47を見失う | Huntedなどに移行 | 戦闘記憶そのものが瞬時に消えるわけではない |
| Combat中に47を再発見する | 攻撃を再開 | 対象の身元が判明している場合 |

## 4. 知覚・情報伝達に関する原則

### 4.1 「出来事の認識」と「犯人の特定」は別

原作を参照するうえで重要なのは、次の情報を同一視しないこと。

1. **異変があったこと**：音、遺体、周囲の騒動を認識。
2. **行為そのものを見たこと**：誰かが襲われる瞬間を視認。
3. **47を行為者として識別したこと**：目撃・報告などにより特定。
4. **戦闘対象として認識したこと**：Combatに入る判断。

公式マニュアルでは「近接アクションの音を聞いた」「銃声を聞いた」「犯罪を目撃した」が別々の通知として扱われている。単純に視界角だけを広げるのではなく、**視覚・音・目撃者の証言・犯人の身元**を別の情報として保持する設計が適切である。

### 4.2 警備員と市民の差

一般市民は重大な異変に対して逃走・通報し、警備員が調査または戦闘を担当する。通報により警備員が犯罪を知っていても、犯人まで特定しているとは限らない。

### 4.3 Combat中のバリエーション

コミュニティ資料では、原作の警備員が遮蔽物を利用する、位置を変える、近距離で別の反応をする、戦闘中にフラッシュ系の演出・行動を取ることなどが報告されている。ただし、**全警備員が常に同じ行動を取るわけではない**。詳細な使用条件や頻度は公式資料で確認できないため、この報告では確定仕様として数値化しない。

## 5. CLEAN HANDSとの差分（既存コード調査に基づく）

2026年11月3日時点に調査したGitHubのPC版では、以下の差分が確認された。

| 項目 | 原作HITMANの挙動 | CLEAN HANDS側の確認事項 | 判定 |
|---|---|---|---|
| 犯行の直接目撃 | 警備員が重大な犯罪を目撃するとCombatへ進み得る | `m3.witness()` → `director.accuse()` が基本的に `alert` へ進む。Combat開始は別条件 | **重要差分** |
| 犯人不明の遺体発見 | 調査・Searching、犯人認定はしない | 発見後に `investigate` へ進む仕組みあり | **方向性は一致** |
| 近接行動の音 | `Close Combat Heard` による異変調査 | 近接アクション目撃処理が視覚中心 | **改善候補** |
| 追跡と戦闘 | HuntedとCombatを区別し、戦闘時には攻撃 | `alert` では追跡・拘束にとどまるケースあり | **重要差分** |
| 追跡だけで逃げられる問題 | 交戦を含む状態遷移が脅威を構成 | 既存設定ではプレイヤーの走行上限4.8m/s、警備員4.1m/s | **ゲーム体験上の課題** |
| 戦闘の行動種類 | 射撃以外の反応が報告されている | 調査範囲では特殊な戦闘行動が限定的 | **後回しでよい課題** |

**重要**：この比較は既存の静的コード調査に基づく。現時点のゲームビルド・F8記録の再実行ではないため、すべてのシーンで現象が発生すると断定しない。

## 6. CLEAN HANDSの受け入れテスト案

| ID | テストシナリオ | 期待されるゲーム内の反応 |
|---|---|---|
| G-01 | 通常の制限区域で発見され、指示に従う | 警告・退去誘導。無条件にCombatへ入らない |
| G-02 | 敵対区域で発見される | 区域の危険度に応じた敵対反応が発生する |
| G-03 | 警備員が47による重大な暴力行為を直接目撃する | 単純な無限追跡にとどまらず、Combatへの妥当な遷移が発生する |
| G-04 | 犯人が不明の遺体を発見する | Searching・調査へ進み、無根拠に47を犯人認定しない |
| G-05 | 47が見えない位置で異変の音だけを認識する | 音の発生地点を調査し、犯人の特定とは区別する |
| G-06 | 一般市民が重大な犯罪を目撃する | 警備員へ報告し、情報の伝達範囲と内容が記録される |
| G-07 | Combat中に視界から消え、再び発見される | Hunted→Combatなど、知識を保持した自然な状態変化 |
| G-08 | 変装を見破られるが暴力行為はしていない | 疑念や拘束など、発砲以外の反応が成立する |

F8ログには、`incident_type`、`observer_id`、`perceived_by`（視覚・音・報告）、`identified_actor`、`state_before`、`state_after`、`transition_reason`、`build_sha` を記録すると、状態遷移を検証しやすい。

## 7. 結論と優先順位

1. **最優先**：重大犯罪の直接目撃とCombat開始のつながりを検証・修正する。
2. **最優先**：遺体発見・音の認識・犯行の直接目撃で、犯人特定の有無を明確に分離する。
3. **次点**：警備員の追跡とCombatを、プレイヤーの行動理由に応じて自然に切り替える。
4. **次点**：F8記録を使い、知覚イベントからNPC状態遷移まで追跡できるようにする。
5. **その後**：戦闘中の移動、遮蔽物、反応のバリエーションなどを磨く。

**設計上の核心**：原作の警備員が脅威になるのは、単に発砲頻度や視力が高いからではなく、**何を見聞きして、何を知り、どの警戒状態へ進むかが一貫しているから**である。
