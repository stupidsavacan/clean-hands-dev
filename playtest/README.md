# CLEAN HANDS プレイテスト（PC版）

シナリオを選んで普通に遊ぶと、起きたことと状態が自動でファイルに保存されます。

## 起動

- `start.bat` をダブルクリックします。ブラウザで http://127.0.0.1:8795/ が開きます。
- 黒い窓（サーバー）は、遊んでいる間は閉じないでください。
- 手で起動する場合は、このフォルダで `python server.py` を実行します。

サーバーはこのPCの中（127.0.0.1）でだけ動きます。記録はどこにも送りません。

## マップ

| マップ | 開くところ | ゲームのファイル |
|---|---|---|
| グランド・マリーナ・ホテル | http://127.0.0.1:8795/ | `..\index.html` |
| 夜会の私邸（試作） | http://127.0.0.1:8795/party | `..\party-prototype.html` |
| クラブ（試作） | http://127.0.0.1:8795/club | `..\club-prototype.html` |

クラブは「通し」で始めます。記録名は `日付-時刻_club-full.json` です。
既存のサーバーを開いたまま更新した場合は、サーバーを起動し直してください。
クラブの **F9** には人物一覧、検査、はしご、区域の移動先が出ます。

### クラブの記録と群衆の分析

- `telemetry` の `foot` に0.5秒ごとの位置、区域、服、姿勢、手に持った物、銃、行動が入ります。
- `sight` に1秒ごとの視線、見える群衆の数と場所番号、視線を遮った場所が入ります。
- `action` は行動の始まりと終わりです。 `reaction` は反応と、その理由・距離・視覚か音かです。
- `draw` は銃を出した瞬間の周囲20mの人物です。その瞬間に反応したかと、視界外や遮蔽物などの理由が入ります。その後の反応は `reaction` に入ります。
- `node analyze-crowd.mjs` を実行すると、`runs/crowd-analysis.json` と `runs/crowd-analysis.svg` に集計します。
- 記録を選ぶには、ファイルのパスを引数に並べます。自動試験の記録はパスを指定したときだけ集計します。
- 図では赤い格子が行動の場所です。群衆の場所には「見えた回数／遮った回数」を表示します。元の記録名と秒数はJSONに入ります。

- シナリオを選ぶ画面の上の「マップ」で、切り替えられます。
- 夜会の私邸の記録は、ファイル名が `日付-時刻_party-シナリオ.json` になります。記録の一覧とメモの一覧は、2つのマップで共通です。
- デバッグ画面（F9）は、マップに合わせて中身が変わります。夜会の私邸では、「イベント」にこのマップのチャンス3つ・行動5つ・フラグが、「移動・時間」の「場所」に抜け道（はしご・雨どい・窓・縁）の両端が出ます。ホテルの樽・カードキー・仕掛けは出ません。

## 遊び方

1. 最初に、シナリオを選びます。
   - **通し（本番どおり）**：0:00から始まり、チャンスは未発見です。
   - **チャンス別（14個）**：「最初の手順に必要な人が現れる時刻」と「チャンスの時間帯」の早い方の、3〜15分前（初期値は7分前）から始まります。たとえばA1は、ソムリエが桟橋に着く5:00が基準です。そのチャンスは発見済み・追跡中で始まります。開始地点・服・道具は本番と同じなので、服や道具は自分で集めます。
2. あとはいつもどおり、外見・準備画面から「作戦開始」します。
3. 画面下の小さな表示（`● REC`）が記録中のしるしです。シナリオ名、経過時間、出来事の数、最後に保存した時刻が出ます。
4. やり直し・準備画面へ戻る・タブを閉じる、のどれでも、それまでの記録は保存されます。次のミッションは同じシナリオの新しい記録になります。
5. シナリオを変えるときは、画面下の「シナリオ変更」を押します（次のミッションから変わります）。
6. 気づいたことや、そのときの判断は **F8** でメモできます（下の「メモ（F8）」）。
7. 体力・服・持ち物・イベントなどをいじるときは **F9** でデバッグ画面を開きます（下の「デバッグ（F9）」）。

## デバッグ（F9）

- 作戦開始後に F9 を押すと、ゲームが一時停止し、右にデバッグ画面が出ます。もう一度 F9（または「閉じる」）でゲームに戻ります。
- **自分**：体力、服（14種）、バレた服を消す、持ち物（ワイヤー・致死毒の数・セラーの鍵・カードキー）、手に持つ物（スパナなど）、銃（持つ・外す・弾）。コインの枚数だけは変えられません。
- **オンオフ**：オンにしたものは、閉じても毎フレーム効き続けます。作戦をまたいで、このブラウザに残ります。オンのあいだは右上に青い帯で出ます。
  - 誰にも見えない（人）／監視カメラに映らない／顔見知りに見抜かれない／服がバレない
  - 体力が減らない／弾が減らない／致死毒が減らない
  - 検問を素通り／警戒度を0に固定／人を止める／死体・気絶が見つからない
  - ほかに、警戒度を0〜3にする、全員を落ち着かせる
- **イベント**
  - チャンス14個：発見、手順を戻す・進める、完了、未発見に戻す、追跡、その時間帯へ
  - 行動：チャンスの各手順（A1の挨拶・樽・一杯・誘う、ほか21個）の「そこへ」（その場所か相手の前へ移動）と「実行」（その場で終わったことにする）
  - 仕掛け：限定ワインの樽の状態、7つの罠の「準備済み」「作動済み」、今すぐ作動
  - フラグ：チャンスの手順に使うもの全部、運転席に座っている
- **人**：全員の一覧（標的が先、近い順、名前で絞り込み）。状態・疑惑・顔のゲージが見えます。そこへ移動／落ち着かせる／気絶／殺す。
- **移動・時間**：1倍・4倍、±1分・±5分、時刻を入れて移動（例 `19:00`）。地図（階を選んでクリックした場所へ移動）、主な場所・出口・部屋へ移動。
- **デバッグを使った作戦は記録しません。** デバッグ画面で何かを変えた時点で、その作戦の記録をやめ、それまでに保存した分（メモの写真も）を消します。オンオフが1つでもオンのまま始めた作戦も、最初から記録しません。画面下の表示が「○ デバッグ中（記録しない）」になります。
- **デバッグ中でも F8 のメモは残せます**（2026-11-02 から）。表示は「F8 メモは残せます」。
  - 遊び全体は記録しません。メモを取ったときだけ、`runs\<日時>_debug.json` に保存します。
  - 中身は、メモの本文・札・写真・そのときの状態・近くの人と、直前60秒の出来事（使ったデバッグのオンオフも入ります）です。
  - 同じ作戦の中のメモは、同じファイルにまとまります。記録一覧では「デバッグ中のメモ」と出ます。
  - ふざけて遊んだ跡は残さず、「これはおかしい」と思ったところだけを残すための仕組みです。
- 開いて見るだけなら記録は続きます。オンオフを全部オフにすると、次の作戦（やり直し・準備画面から・再読み込み）からまた記録します。
- 一時停止中に変えたことは、ゲームに戻ってから効くものがあります（倒した人の「排除」の記録など）。

## メモ（F8）

- 作戦開始後、いつでも F8 を押すとゲームが一時停止し、メモ欄が開きます。
- 書いて **Enter** で保存し、ゲームに戻ります。Shift+Enter は改行、**Esc** はやめる（保存しない）です。
- 「バグ」「方法がない」「難しすぎ」「簡単すぎ」「分かりにくい」「アイデア」の札を付けられます（いくつでも）。
- メモと一緒に、F8を押した瞬間の次のものが自動で残ります。
  - 画面の写真（`runs\<記録名>_memo<番号>.jpg`）
  - ゲーム内の時刻・階・位置・服・手に持った物・警戒度・疑惑・標的3人の位置（1秒ごとの記録と同じ中身）
  - 半径12m以内の人（名前・距離・状態・疑惑・こちらが見えているか）
  - 直前の出来事8件
- 一覧：http://127.0.0.1:8795/memos （全部の記録のメモを新しい順に、写真つきで）。記録の一覧にもメモの数が出ます。
- 結果画面でも書けます（その記録に足されます）。

## 記録

- 保存先：このフォルダの `runs\`。1回のミッションが1ファイルです（`日付-時刻_シナリオ.json`）。
- 一覧：http://127.0.0.1:8795/runs （開始時刻・シナリオ・時間・結果・ランク・ゴースト・崩れた理由・倒した人）。
- 保存のタイミング：5秒ごと、タブを離れたとき、ミッションが終わったとき、ページを閉じたとき（閉じるときは終わり方だけを送り、直前の保存に足します）。
- **チャンスの判定**：チャンス別のシナリオでは標的が1人なので、結果画面まで行けません。そこで、標的が死んで10秒たった時点で判定し、画面下に黄色で出して記録します（`verdict`）。一覧の「ランク」の欄に「成立・事故」などと出ます。
  - チャンス成立：そのチャンスの手順どおりに倒せたか
  - 事故／殺人／戦闘：倒したときの判定
  - ゴースト維持／崩れ（理由）：その時点でゴーストの条件が残っているか

### ファイルの中身

| 項目 | 内容 |
|---|---|
| `meta` | シナリオ、開始時刻、ゲーム内の開始時刻、持ち込んだ道具、画面サイズ |
| `events` | 起きたこと全部：着替え、見つかった、死体・気絶の発見、殺し（事故か殺人か、その理由）、チャンスの進み具合、罠の準備・作動、警戒度、撃ち合い、録画、標的の予定（標的3人だけ）。それぞれに、そのときの自分の位置と服。同じ人の「見つかった」「目撃・通報」「撃たれた」が3秒以内に続いたときは1件にまとめ、回数（`repeat`）と最後の時刻（`lastPlay`）を付けます |
| `samples` | 1秒ごとの状態：位置・階、服、バレた服、持ち物、銃、体力、警戒度、いちばん怪しんでいる人と疑惑、怪しんでいる人数、一時停止・地図、fps、標的3人の位置と行動（`targets`）、半径12m以内の人（`near`：名前・距離・状態・疑惑・見えているか） |
| `memos` | F8のメモ：文章・札・その瞬間の状態（`state`）・近くの人（`near`）・直前の出来事（`recent`）・写真のファイル名（`shot`） |
| `verdict` | チャンス別のシナリオで、標的が死んで10秒後の判定（上の「チャンスの判定」） |
| `end` | 終わり方、結果（点数・ランク・ゴーストを崩した理由）、倒した人と判定、チャンスの状態、録画の状態 |

時刻は `play`（記録の開始からの秒）と `clock`（ゲーム内の時刻の秒）の2つです。

## しくみ

- ゲーム本体は `..\index.html`（ホテル）と `..\party-prototype.html`（夜会の私邸）を、そのまま使います。サーバーが配信するときに、記録用の `playtest.js` とデバッグ画面の `debug.js` を足します。
- チャンス・予定・行動のデータは、`/api/chances` などに `?map=party` を付けると、夜会の私邸のもの（`party-chances.json` など）が返ります。
- ゲーム側の変更は1つだけです。デバッグ用の `__cleanHands` に、出来事の流れを受け取る `eventBus` を足しました。
- ゲームを作り直したとき（`npm run build` と `node scripts/standalone.mjs`）は、サーバーを起動し直さなくても、次に開いたときから新しい版になります。
